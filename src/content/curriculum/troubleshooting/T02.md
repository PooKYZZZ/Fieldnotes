# NGINX returns 502

## Observation

NGINX serves static files but proxying /api fails after an app update.

## Investigation

1. Save the time, request path and sanitized response. Confirm whether the same health check works directly against the owned API.
2. On the lab host, compare the API listener and the proxy request:

   ```bash
   ss -ltn
   curl -i --max-time 3 http://127.0.0.1:8000/health
   curl -i --max-time 3 http://127.0.0.1:8080/api/health
   ```

   Adjust the paths and ports to match the disposable lab. A direct success with a proxied 502 narrows the issue to the proxy-to-upstream path; it does not identify which setting is wrong.
3. Validate the lab configuration with `nginx -t` before a reload. Check the exact upstream scheme, service name/address, port and path.
4. Read only the matching proxy and API log window. Compare timestamps and distinguish refused connection, timeout, name lookup failure and an API response.
5. Restore the last known-good lab mapping and repeat the same direct and proxied health checks.

## Safety constraint

Work only on disposable resources or services you own, and record initial evidence before applying a
fix.

## Hint

A restart is an experiment, not a diagnosis.


## Completion evidence

Include direct and proxied health results, the sanitized matching NGINX log entry, the exact lab mapping changed, configuration validation, and the same successful proxied check after rollback.
