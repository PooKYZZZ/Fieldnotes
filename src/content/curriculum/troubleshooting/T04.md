# Missing Compose data

## Observation

A database appears empty after you recreate the stack.

## Investigation

1. Stop before restarting or initializing the database. Record the Compose directory and project name that were used before the data appeared missing.
2. Inspect the current project and declared named volumes without removing anything:

   ```bash
   docker compose -p fieldnotes-demo ps -a
   docker compose -p fieldnotes-demo config --volumes
   docker volume ls --filter "label=com.docker.compose.project=fieldnotes-demo"
   ```

   Replace the example project name with the exact owned lab name. Compose resolves resource names using its project configuration; another project name can point the same file at a different volume.
3. Inspect the specific database container mount and compare the source volume with the one that holds the expected data:

   ```bash
   docker inspect fieldnotes-demo-db --format '{{json .Mounts}}'
   docker volume inspect fieldnotes-demo_data
   ```

   Substitute the exact container and volume names from the lab. Do not publish the full inspect output if it contains private paths or environment details.
4. Review the database image's first-run initialization behavior and startup logs. Empty initialization can mean a new empty volume was mounted, not that old records were deleted.
5. Preserve both candidates. Confirm the correct source with an authorized backup or read-only check before any recovery action; never run `down -v`, prune, or a fresh initialization while investigating.

## Safety constraint

Work only on disposable resources or services you own, and record initial evidence before applying a
fix.

## Hint

Different project names can create different volume names.

## Completion evidence

Identify the original project and volume from its mounts, explain why the recreated stack used another data source, and show that the expected synthetic record remains in the preserved candidate. Do not delete either volume during diagnosis.
