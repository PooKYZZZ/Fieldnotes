# Rollout stuck

## Observation

A Kubernetes Deployment never reaches desired availability.

## Investigation

1. Confirm the current context is the named local lab before inspecting or changing resources:

   ```bash
   kubectl config current-context
   kubectl get deploy,pods,svc -n fieldnotes-a18
   kubectl rollout status deployment/status-api -n fieldnotes-a18 --timeout=30s
   ```

2. Describe the Deployment and the affected Pod, then inspect recent namespace events. Look for image-pull errors, scheduling/resource constraints, failed probes and readiness transitions.
3. Compare container port, Service target port, selector labels and readiness path. `Running` means the container started; only ready selected Pods appear as usable service endpoints.
4. Inspect rollout history and compare the current template with the last known-good revision. Do not repeatedly delete Pods; the Deployment controller may recreate the same failing template.
5. In the local namespace only, correct the identified manifest issue, wait for rollout completion, and repeat the same endpoint check.


## Safety constraint

Work only on disposable resources or services you own, and record initial evidence before applying a
fix.

## Hint

A Pod in Running state may still be NotReady.

## Completion evidence

Record the local context and namespace, the blocking Pod condition/events, the corrected manifest field, completed rollout, ready Service endpoint and repeatable endpoint check.
