# CI works locally

## Observation

A test passes on your laptop and fails on a clean GitHub runner.

## Investigation

1. Identify the failing workflow run, job, step and first relevant error. Separate the first failure from later cancellation messages.
2. Compare the runner operating system, runtime versions, lockfile install command and environment variable names with the documented local setup. Do not print secret values.
3. In a clean disposable checkout, use the same lockfile-based install and test command as the workflow. Record versions and exit status rather than relying on a developer machine with cached packages.
4. Check for case-sensitive paths, untracked generated files, current-directory assumptions, time zone, port collisions, test-order dependence and shared test records.
5. Change one verified difference in the practice branch and rerun the same test. A local pass narrows the difference; it does not show that the hosted workflow passed.

## Safety constraint

Work only on disposable resources or services you own, and record initial evidence before applying a
fix.

## Hint

A hidden local dependency is evidence, not proof that the runner is wrong.

## Completion evidence

Record the first failing runner step, the verified local/runner differences, a clean-checkout reproduction, one minimal correction, and the resulting rerun. Distinguish that evidence from any hosted workflow that you did not execute.
