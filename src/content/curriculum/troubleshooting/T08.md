# Terraform surprises

## Observation

Terraform proposes replacing a resource after you changed a seemingly minor variable.

## Investigation

1. Confirm the working directory, selected workspace and provider context before interpreting the plan:

   ```bash
   terraform workspace show
   terraform providers
   terraform plan
   ```

   Run these only in the activity's disposable local workspace. A plan refreshes observations and proposes changes; it does not authorize applying them.
2. Find the resource address and the exact attributes marked for update, replacement or deletion. Compare those fields with the provider documentation and the variable change.
3. Identify whether the affected object holds stateful data or is referenced by another resource. Do not expose state or plan files in shared logs; they can contain sensitive values.
4. Compare the plan with a written prediction. If any unexpected resource is replaced or destroyed, stop and investigate workspace, provider, state path and configuration.
5. In the owned lab only, keep the plan un-applied while you explain the cause. Apply or destroy only after an explicit review confirms the resource and its data are disposable.

## Safety constraint

Work only on disposable resources or services you own, and record initial evidence before applying a
fix.

## Hint

Do not apply or refresh state carelessly merely to remove a warning.

## Completion evidence

Include the selected workspace/provider, the relevant plan action and attributes, whether data loss is possible, and the prediction you compared with the plan. State explicitly that the plan was not applied if any destruction or replacement remains unexplained.
