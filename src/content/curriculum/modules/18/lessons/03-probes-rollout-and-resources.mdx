    <p>Readiness decides whether a container should receive Service traffic; it does not restart the container. Liveness can restart a container after a defined failure. A startup probe gives a slow-starting application time before liveness checks begin. Poorly chosen probes can remove healthy Pods or create restart loops. Resource requests inform scheduling; limits constrain use. A rollout is safe only when enough replicas are ready and compatible with the current data and dependencies.</p>
