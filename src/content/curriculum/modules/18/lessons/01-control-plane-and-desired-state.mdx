<ConceptSection layout="split">
  <div className="learning-concept-copy">
    <p>The API server stores the declared objects; controllers compare desired state with observed state and take action to close the gap. A Deployment creates and manages ReplicaSets, which maintain the requested number of Pods. A Pod can be rescheduled or replaced, so do not depend on its IP or local writable layer as durable application state.</p>
    <p><strong>Worked example:</strong> If a Deployment requests three replicas but only two Pods are ready, its controller keeps reconciling toward three. Compare the Deployment's desired and available counts with its ReplicaSet, Pods, and recent events to find whether the missing replica is pending, crashing, or unable to pass its configured readiness check.</p>
    <p><strong>Interpret the result:</strong> A controller reporting three ready replicas is evidence that the declared readiness checks currently pass; it is not proof that every user workflow is correct. A replacement Pod also has a new identity, so durable application data belongs in an explicitly managed volume or external store.</p>
