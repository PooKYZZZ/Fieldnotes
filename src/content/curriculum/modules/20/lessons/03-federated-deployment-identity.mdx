<ConceptSection layout="split">
  <div className="learning-concept-copy">
    <p>Where the cloud and CI provider support it, OpenID Connect federation can exchange a short-lived workflow identity token for cloud credentials. Trust conditions should restrict the repository, branch, environment or workflow that may request the identity. Federation reduces the need to store a long-lived cloud key, but it does not make a workflow safe by itself: protect workflow edits, apply least privilege and audit each deployment.</p>
    <p>When reviewing a trust policy, identify the issuer and audience it accepts, then check the subject or other claims that limit which repository and deployment context can request access. A policy for a protected production environment should not silently accept every branch in the repository. Claim formats vary by CI provider and by whether an environment is used; check that provider's current documentation and never print a live token to inspect it. GitHub's <a href="https://docs.github.com/en/actions/security-for-github-actions/security-hardening-your-deployments/about-security-hardening-with-openid-connect">OIDC guidance</a> describes its token and trust configuration.</p>
