# Module 02: Linux command line and filesystems

## Introduction

Use the terminal confidently enough to inspect a system without guessing what each command will
change.

## Prerequisites

Module 01 or equivalent OS understanding.

## Learning question

How can a short command pipeline find a useful clue in system files without changing the evidence you are inspecting?

## Lesson

### Paths, filesystems, and mounts

Linux presents one directory tree rooted at `/`. A mounted disk or network filesystem appears at a directory in
that tree, so the path does not reveal which device stores the bytes. An absolute path starts at `/`; a relative path
starts from the process's current working directory. `pwd` answers where a shell is operating, while `find` and
`stat` help inspect files and metadata.

### Streams, pipes, and redirection

Each process can read standard input and write standard output and standard error. A pipe connects one process's
output to the next process's input; redirection sends a stream to a file or another destination. The shell opens
redirection targets before starting the command, so `>` can truncate an existing file even if the command later
fails. Use a new report path or append with `>>` when that is intended.

```diagram
find files ──stdout──▶ grep for a pattern ──stdout──▶ head a short preview
   stderr ───────────────────────────────────────────▶ terminal
```

### Shell expansion and safe inspection

The shell expands variables, wildcards and command substitutions before passing arguments to a program. Quoting
preserves a value as one argument and prevents accidental wildcard expansion. Before changing anything, inspect
targets with `pwd`, `ls -la`, `find`, `head` or `less`; use `--help` and the manual page to confirm options.

This searches log files and displays a limited preview without editing them:

```bash
grep -RIn --include='*.log' -- 'ERROR' ./logs | head -n 20
```

The pattern after `--` is treated as a pattern even if it begins with a dash. A shell pipeline can hide an earlier
command's exit status; in Bash, `set -o pipefail` makes a failing pipeline visible, though scripts still need explicit
handling for expected cases such as no matches.

### Exit status and package managers

Commands normally return status `0` for success and nonzero for a failure or special condition. Terminal text is
useful, but scripts should also check status before acting on output. Package managers track installed versions,
dependencies and repository origin. Copying a binary into a directory does not update that inventory, so the system
cannot reliably upgrade, verify or remove it later.

## Guided practice

Create a disposable directory with sample logs and filenames containing spaces. Use `find`, `grep`, `sort`, `wc`,
`head` and `less` to answer one question; redirect the report to a new file, then inspect it and the command's exit
status. Compare expected and actual results before building the inventory in Activity A02.

## Common mistakes

Using sudo for everything, editing system files without backups, overlooking hidden files, or
accidentally truncating a log with > instead of >>.

## Mini-lab

Build a command-line directory inventory that records names, types, sizes and ownership into a
timestamped report.

## Readiness check

From memory, find a file by name and content, explain which stream a pipe carries, and predict whether a redirection
will append or truncate before running it. Reproduce your directory inventory without a GUI.

## Recall question

In `command > report.txt 2>&1`, which output streams go to `report.txt`, and what happens to an existing file with that name?

## Recall explanation

The shell opens `report.txt` for standard output, truncating it if it already exists; `2>&1` then directs standard
error to the same destination as standard output. Redirection order matters because the second operation copies the
current destination of descriptor 1. Use a new path or append operator when preserving earlier output matters.
