# Module 06: Bash and Python for operational automation

## Introduction

Build small trustworthy tools before delegating important tasks to automation.

## Prerequisites

Modules 02-05.

## Learning question

How do you automate a repeated system check without turning an unexpected input or command failure into a destructive or misleading result?

## Learning objectives

- [Bash for small system workflows](#module-06-bash-for-small-system-workflows)
- [Python for structured operations](#module-06-python-for-structured-operations)
- [Testing and failure handling](#module-06-testing-and-failure-handling)

## Lesson

Bash is good for composing system commands and short administrative workflows; Python is usually easier for
structured data, error handling and substantial reusable utilities. Choose the simpler tool for the actual task instead
of using Python or Bash automatically.
In shell scripts, quoting and exit handling are safety features: an unquoted variable can split unexpectedly, and a
pipeline may hide the failure you care about. In Python, handle command failures explicitly, validate input, use
timeouts for network requests and do not silence exceptions merely to keep a script running.
Reproducibility matters. Manage Python dependencies in an isolated virtual environment, document requirements
and write tests around parsing and decision logic. For a maintenance tool, a dry-run mode and clear failure reporting
can be more valuable than adding new features.

### Bash for small system workflows

Bash is useful when a task composes existing command-line tools. Variables, functions, tests and pipes can make a
short procedure repeatable, but the shell expands values before invoking each program. Quote variables that should
remain one argument, and pass untrusted input as data rather than building a command string from it.

`set -o pipefail` helps a pipeline report a nonzero status from an earlier command. It is not a replacement for
designing expected failure branches: commands such as `grep` commonly return a nonzero result when no match exists.
Preview target files before changing them and prefer a read-only default.

### Python for structured operations

Python is generally easier to maintain when a task parses structured data, validates several inputs or needs explicit
error handling. A virtual environment separates a project's packages from the system interpreter. Use the standard
library where it is enough, and make process and network boundaries explicit with timeouts and checked outcomes.

```python
import subprocess

result = subprocess.run(
    ["df", "-h", "/"], check=True, capture_output=True, text=True, timeout=5
)
print(result.stdout)
```

An argument list avoids shell parsing, `check=True` reports a failed command, and the timeout prevents a stuck
process from waiting forever. Catch only errors the program can handle usefully; do not suppress an exception just
to make the script appear successful.

### Testing and failure handling

Keep decision logic testable with normal, empty, malformed and missing inputs. A useful operational tool says which
check failed and exits with an appropriate nonzero status. A dry-run mode can show the intended change before a
privileged action runs. Document dependencies and the command to run tests so another machine can reproduce the
result.

For a small project, a few focused tests of parsing and failure handling provide more value than adding a framework
or wrapper for every command.

## Guided practice

Write one Bash disk-space report and one Python JSON log summarizer. Test a normal file, an empty file, malformed
JSON and a missing path. Record which errors are reported, what exit status appears, and verify that the scripts do
not alter source files before starting Activity A06.

## Common mistakes

Running arbitrary shell input from external data, using broad recursive deletes, or assuming scripts
succeed without checking exit codes.

## Recall question

What are the important differences between calling `subprocess.run([...])` with an argument list and constructing a shell command string?

## Recall explanation

An argument list passes each value as a distinct argument without asking a shell to expand it, reducing quoting
mistakes and command-injection risk. With `check=True`, a failing command raises an exception instead of silently
looking successful. A timeout bounds how long the parent waits. The caller still needs to handle errors and validate
outputs according to the task.
