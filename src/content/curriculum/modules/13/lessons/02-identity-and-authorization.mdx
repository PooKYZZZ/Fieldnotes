<ConceptSection layout="split">
  <div className="learning-concept-copy">
Azure RBAC governs actions on cloud resources; a Linux account governs actions inside the guest; application roles
govern what a user can do through the service. These are different identities and trust boundaries. Use the smallest
role and scope that completes the task, require MFA where supported, and avoid using an Owner account for ordinary
deployment. A network allow rule is not user authentication.

For one release, ask three separate questions: can the operator update the Azure resource, can the deployment
identity reach and configure the guest, and can the application user perform the intended action? Passing one check
does not grant or prove the other two. Test each with the identity that will actually perform that operation, and
record the scope where access is granted.
