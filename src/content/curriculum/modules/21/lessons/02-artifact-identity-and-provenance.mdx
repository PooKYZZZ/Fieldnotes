<ConceptSection layout="split">
  <div className="learning-concept-copy">
    <p>An SBOM lists known software components and versions. Provenance records how an artifact was produced and which inputs or workflow created it. A signature or attestation can help verify origin and integrity when the signing identity and verification policy are trustworthy. These records improve traceability; they do not prove the code is correct or free of vulnerabilities.</p>
    <p>Trace one release as <code>reviewed commit → trusted build workflow → image digest → attestation</code>. Before deployment, check that the digest being promoted matches the tested artifact, and that the attestation identifies an approved source revision and builder. A mismatch means the evidence does not describe the artifact in hand. A valid match establishes origin according to that trust policy; tests, vulnerability review and runtime checks still answer different questions. See the <a href="https://slsa.dev/spec/v1.2/verifying-artifacts">SLSA provenance guidance</a> and <a href="https://docs.github.com/en/actions/security-for-github-actions/using-artifact-attestations">GitHub artifact attestations</a>.</p>
