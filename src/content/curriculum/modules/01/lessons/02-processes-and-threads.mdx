**What can run independently, and what is shared?** A process is an isolation and resource boundary. A thread is an execution path within that process. Threads in one process share its address space and many resources, including open file descriptors, but each thread has its own execution state and stack.

The scheduler chooses among runnable threads. A thread can be running on a CPU, ready to run, or blocked while waiting for an event such as input from a file or socket. A blocked thread is still part of a live process, but it is not continuously using CPU. Sharing memory lets threads exchange data quickly; it also means updates need coordination to avoid races. Figure 2 compares single-threaded and multithreaded processes: the threads use shared process code, data, and files while keeping separate stacks and execution state.

Inspect the thread count for a process you own with `ps -o pid,nlwp,comm -p PID`, replacing `PID` with a value from the previous command. `nlwp` is the number of lightweight processes (threads) reported for that process by procps. It is a snapshot: short-lived threads can appear or exit between observations.


**Check:** A service is idle while waiting for a response from a disk. Is the waiting thread necessarily consuming CPU? What could you inspect to distinguish waiting from active work?
