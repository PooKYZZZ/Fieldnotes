**What is different between an application on disk and one that is running?** A program is a file containing instructions and data. When you launch it, the operating system creates a process: a running instance with an identity, an address space, resources such as open files, and at least one thread of execution.

On Linux, a shell commonly asks the kernel to create a child process and then execute a program in it. The `execve` system call replaces the calling process's program image with the new program; it does not itself create a new process. The kernel maps the program and its required data, prepares the initial state, and begins execution.

### Trace a parent process in your VM

The **PID** identifies a process. The **PPID** in that process’s row is the PID of its parent. Each concurrently running copy of a program has its own PID.

If you’re new to the terminal, [prepare the disposable VM and try a pipe](/guide#lab-readiness). In your Linux terminal, list the processes.

```bash
ps -eo pid,ppid,comm,state --sort=pid | head
```

Example output with illustrative IDs.

```text
  PID  PPID COMMAND   S
 2831  2802 bash      S
 2914  2831 sleep     S
```

The `sleep` process has PID `2914`. Its PPID is `2831`, which matches the `bash` row. The `S` state means interruptible sleep at the moment of the snapshot. Your IDs will differ. Pick a process you recognize and find the row whose PID matches its PPID. If the parent is outside the first ten rows, run `ps -p PARENT_PID -o pid,ppid,comm,state`, replacing `PARENT_PID` with the number you found.
