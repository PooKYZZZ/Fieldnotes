<ConceptSection layout="split">
  <div className="learning-concept-copy">
    <h4>Restore without risking the source</h4>
    <p>Choose a known-good backup and restore it to a clean, isolated destination. Preserve the original backup and the damaged source so the result can be checked and the exercise repeated. Keep the restored copy separate from valuable or live data.</p>
    <h4>Verify more than the command exit code</h4>
    <p>Check the database integrity result and expected synthetic identifiers first. Then test the application’s read path and required configuration when the exercise includes an application. Record which checks passed, their timestamps, the newest data point recovered, and the time the tested service became usable.</p>

<Callout title="Do not equate recovery actions" tone="note">
  Restart returns a process to execution. Rollback changes a release. Restore recovers data or system state from a saved copy. Failover redirects work to another target. A real recovery plan may combine these actions, but evidence for one does not prove the others.
</Callout>
