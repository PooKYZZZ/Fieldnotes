# Infrastructure and application security

## Prerequisites

Complete or study Module 19 in 03_Operations_and_Security.pdf.

## Challenge

List exposed ports and identities on your VM. Close one unnecessary path, test before/after and
document residual risks.

## Build outcome

Write a one-page threat model and a hardened configuration checklist for the Status API lab.

## Environment

Use a disposable VM or a copied local service configuration that you own. Take a snapshot or backup. Do not modify
the host firewall or close ports on shared, school, work, or production infrastructure.

## Lab steps

1. Inventory running services, listening ports, service identities, and the test application's data flows.
2. Draw the trust boundaries and list assets, likely threats, existing controls, and residual risks.
3. Choose one unnecessary path in the disposable lab and record its current state.
4. Change only that lab configuration; repeat the same connection test and verify required health and administration
   paths still work.
5. Review process privileges and exposed interfaces. Document the control evidence and any remaining risk.

## Hints

```bash
ss -ltn
ps -eo user,pid,comm
```

A port listing shows listeners, not whether a path is reachable from every network. Keep the test on loopback or the
isolated VM network.

## Verification

- The threat model names assets, boundaries, entry points, controls, assumptions, and residual risk.
- Before/after connection results show the intended path changed and required paths still work.
- Every running service and privilege has a stated purpose or a follow-up decision.
- No real user data, credentials, or public addresses appear in evidence.

## Troubleshooting

- **A connection still succeeds:** check both host and application listeners, and confirm the test used the expected
  address and port.
- **The service becomes unreachable:** restore the snapshot or revert only the lab change before proceeding.
- **An unexpected process is found:** record it and investigate rather than stopping an unrelated service.

## Cleanup

Restore the saved VM/firewall configuration and verify the original lab service state. Remove only test users or services created for this activity.

## Evidence to record

One short readme/note containing expected result, actual result, commands or test case
evidence, and a failure case; avoid full solution copy-pastes.

## Self-check

Justify privileges, services and ports; demonstrate one verified control and identify at least one
unresolved risk.


## Independent reflection

What would you inspect first if this stopped working tomorrow? What can you verify without asking anyone
else?
