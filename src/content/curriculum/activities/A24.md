# DevSecOps integration and architecture judgment

## Prerequisites

Complete or study Module 24 in 03_Operations_and_Security.pdf.

## Challenge

Audit your capstone architecture using an explicit rubric: functionality, reliability, security,
maintainability, cost and independent explainability.

## Build outcome

Produce a concise architecture decision record and a complete operational demonstration for
your capstone.

## Environment

Use a local capstone copy, its documentation, and a disposable test environment. Do not deploy changes to a real
service as part of this assessment.

## Lab steps

1. Trace one important user request through the architecture and identify the owner and failure mode of each
   component.
2. Score functionality, reliability, security, maintainability, cost, and explainability using evidence, not
   unsupported claims. Mark unknowns separately.
3. Select one important design trade-off and write an Architecture Decision Record with context, options, decision,
   consequences, and a revisit trigger.
4. Run one safe end-to-end smoke check and one controlled failure/recovery test against the local capstone.
5. Prepare a demonstration that includes startup, health, logs, backup or recovery evidence, and how to roll back.

## Hints

- Distinguish code-level tests, local runtime checks, hosted CI evidence, and production evidence.
- A passing health endpoint proves only the behavior it exercises; state what remains unverified.
- Prefer one focused improvement with measurable acceptance criteria over a broad rewrite.

## Verification

- Every score links to an artifact, test, or clearly labeled evidence gap.
- The decision record explains a rejected alternative and operational consequences.
- The smoke test and recovery test are repeatable on the documented environment.
- Another learner can follow the README without needing private configuration or undocumented credentials.

## Troubleshooting

- **The rubric relies on opinion:** replace each claim with a test, source, diagram, or explicit uncertainty.
- **The smoke test passes but the demo is incomplete:** check recovery, rollback, logging, and setup steps separately.
- **A test requires production credentials:** stop and replace it with an authorized local fixture.

## Cleanup

Remove only test deployments and synthetic data created for this review. Keep the ADR, redacted diagram, and evidence links in the capstone portfolio.

## Evidence to record

One short readme/note containing expected result, actual result, commands or test case
evidence, and a failure case; avoid full solution copy-pastes.

## Self-check

Defend one important tradeoff, reproduce a release safely and demonstrate recovery from a controlled
failure.

## Independent reflection

What would you inspect first if this stopped working tomorrow? What can you verify without asking anyone
else?
