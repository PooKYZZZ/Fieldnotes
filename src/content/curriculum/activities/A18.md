# Kubernetes architecture, workloads and operations

## Scenario

A Deployment can report running Pods while its Service selects no ready endpoints or a rollout is blocked by image or probe errors.

## Learning objectives

- Confine all Kubernetes objects to a named local cluster context and namespace.
- Observe how a Deployment replaces a deleted Pod and how its Service selects endpoints.
- Cause one manifest-only rollout fault, diagnose events and restore a known-good revision.

## Expected observations

The controller creates a replacement for a deleted matching Pod. Service endpoints appear only for Pods selected by its labels and marked ready. A bad image reference or readiness path is reflected in Pod state, events or rollout status; after restoring the known-good manifest, the rollout and in-cluster request should succeed.

## Prerequisites

Complete or study Module 18 in 03_Operations_and_Security.pdf.

## Challenge

Deploy an API locally; scale replicas, delete one Pod, inspect replacement behavior and test service
discovery. Also: Push a broken image tag or bad readiness route in a lab; inspect rollout status; roll back to a working
revision.

## Build outcome

Create a small Deployment and Service for your status API in an isolated local cluster. Then:
Demonstrate a controlled Kubernetes rollout, failed rollout diagnosis, and recovery in a local cluster.

## Environment

Use an isolated local Kubernetes cluster such as kind, minikube, or k3d. Before changes, check the active context
and cluster name. Never use a shared or production context for this lab.

## Lab steps

1. Confirm the active context is your local lab and create a dedicated namespace for this activity.
2. Deploy the Status API as a Deployment with a Service. Inspect Pods, labels, events, and endpoint discovery.
3. Scale the Deployment, delete one matching test Pod, and watch the controller replace it. Test service discovery
   from an allowed in-cluster client.
4. In the lab manifest only, set an intentionally unavailable image tag or incorrect readiness path. Observe
   rollout status and events; do not push the image to a registry.
5. Restore the known-good setting, wait for a successful rollout, then rehearse rollback to the recorded working
   revision and verify the endpoint.

## Hints

```bash
kubectl config current-context
kubectl get deploy,pods,svc -n fieldnotes-a18
kubectl describe deployment status-api -n fieldnotes-a18
kubectl rollout status deployment/status-api -n fieldnotes-a18
kubectl rollout history deployment/status-api -n fieldnotes-a18
```

Use resource requests and readiness/liveness probes that match the test application. A Ready Pod, a running
container, and a reachable Service answer different questions.

## Verification

- All resources are confined to the dedicated local namespace.
- Deleting one Pod causes the Deployment controller to create a replacement.
- The Service selects the intended Pods and the endpoint works after recovery.
- The bad revision is diagnosed from events/probe state and the working revision is restored and tested.

## Troubleshooting

- **Unexpected context:** stop before applying anything; select the named local context and verify it again.
- **Pod is Pending:** inspect events and resource requests rather than repeatedly deleting it.
- **Image cannot be pulled:** confirm the local image is available to the cluster runtime or use a local image-load step.
- **Readiness fails:** check the configured path, port, and application bind address before rollback.

## Cleanup

Delete only namespace `fieldnotes-a18` after confirming the current context is still the local cluster. Stop the local cluster when finished; do not remove unrelated contexts or cluster data.

## Evidence to record

Include the verified local context and namespace, resource names, Pod replacement and Service endpoint observations, the failed revision events, restored rollout and endpoint check. Do not include production cluster details.

## Self-check

probes, resource controls and safe rollout conditions without following exact tutorial steps.
