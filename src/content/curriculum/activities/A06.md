# Bash and Python for operational automation

## Scenario

Small operations scripts often fail at the boundaries: missing input, malformed records, empty files, paths with spaces and unsafe assumptions about command output.

## Learning objectives

- Build a read-only disk report and a JSON summary over synthetic fixtures.
- Handle valid, empty, malformed and missing inputs with clear exit behavior.
- Verify shell syntax, Python results and safe diagnostic output.

## Expected observations
The valid JSON array should yield exactly two records: one with level `INFO` and one with level `ERROR`. The valid empty array should report zero records without a parse error. The zero-byte file and malformed JSON should be diagnosed as invalid JSON; the missing path should be reported as a file-access error. The disk report should read only the selected path's filesystem metadata. `bash -n` checks shell syntax but does not prove runtime behavior; `--help` should exit without performing the report.

## Prerequisites

Complete or study Module 06 in 01_DevOps_Foundations.pdf.

Technical references: Python [`argparse`](https://docs.python.org/3/library/argparse.html), Python [JSON errors](https://docs.python.org/3/library/json.html), and [Bash pipelines](https://www.gnu.org/software/bash/manual/html_node/Pipelines.html).

## Challenge

Write a Bash disk-space report and a Python JSON log summarizer. Create test inputs that include
missing, malformed and empty files.

## Build outcome

Build a personal sysadmin CLI that reports disk usage, service status and connectivity, with --help
and a safe read-only default.


## Environment

Use a local development directory with toy files and synthetic JSON logs. Run the scripts as your normal user; the
exercise must not modify system services, disks, or network configuration.

## Lab steps
1. **Choose a temporary working directory** whose name contains a space, so quoting is tested. Keep all fixtures and output there; run as your regular user.
2. **Create synthetic JSON fixtures.** Use two valid records, a valid empty array, a zero-byte file, malformed JSON, and one path that does not exist:

   ```bash
   printf '%s\n' '[{"level":"INFO","message":"ready"},{"level":"ERROR","message":"sample failure"}]' > "$work/events.json"
   printf '[]\n' > "$work/empty-records.json"
   : > "$work/zero-byte.json"
   printf '{not valid JSON\n' > "$work/malformed.json"
   ```

   `[]` is valid JSON with zero records; a zero-byte file is not a JSON document. Keep both cases so they cannot be silently treated as the same input.
3. **Implement the read-only disk report.** Accept a path argument (defaulting only to the lab directory), show a `--help` message, and call `df -h -- "$target"`. Explain that the result describes the filesystem containing that path, not a forecast of future capacity.
4. **Implement the JSON summarizer.** Use `argparse` for the input path, `json.load` to parse it, and handle `FileNotFoundError`, `JSONDecodeError`, and a valid non-list or malformed record separately. For the valid fixture, independently predict two records: one `INFO`, one `ERROR`.
5. **Test each boundary.** Run `bash -n`, `--help`, the valid file, the empty array, zero-byte file, malformed file, and missing path. Check process exit codes and confirm diagnostics go to standard error without printing entire file contents.
6. **Review a deliberate defect.** Introduce one harmless syntax or input-path mistake in your own script, observe the failure, then correct it. Record the failed expectation, evidence, and correction before cleaning up the fixtures.

## Hints
```bash
bash -n ./disk-report.sh
./disk-report.sh --help
df -h -- "$work"
python3 -m json.tool "$work/events.json"
python3 ./summarize.py "$work/events.json"
```

Catch expected input errors specifically and write a short message to standard error; avoid a broad `except Exception` that hides programming defects. Python's `json.JSONDecodeError` includes line and column information. Do not use `eval`, print environment values, or build shell commands from file content.

## Verification

- `--help` explains usage without running the report.
- Valid input produces the expected summary; empty, malformed, and missing inputs fail clearly without a traceback.
- The disk report is read-only and returns a nonzero status when a real error prevents a complete report.
- A reviewer can reproduce each case from the README using the synthetic fixtures.

## Troubleshooting

- **Shell script behaves differently than expected:** run `bash -n` first, then enable a controlled test with a
  temporary working directory.
- **JSON parsing fails:** inspect the fixture syntax; report line and column where available without echoing data.
- **A test succeeds unexpectedly:** verify that the script did not silently substitute an empty result for an error.
- **Paths with spaces fail:** quote variables and test with a temporary directory whose name contains a space.

## Cleanup

Delete only the temporary fixtures and reports created for this activity. Keep source scripts and sanitized test output in your learning repository.

## Evidence to record

Include the script purpose and arguments, syntax/test commands, expected and observed results for valid, empty, malformed and missing inputs, exit behavior, and the sanitized error message. Keep the synthetic fixtures reproducible.

## Self-check

Create and explain a small script without generated code; show both a normal run and a controlled
failure with a useful error message.
