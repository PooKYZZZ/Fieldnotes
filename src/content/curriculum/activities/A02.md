# Linux command line and filesystems

## Prerequisites

Complete or study Module 02 in 01_DevOps_Foundations.pdf.

## Challenge

Practice find, grep, sort, cut, wc, less, head, tail, tee and shell redirection. Compare file contents without
copying answers from a tutorial.

## Build outcome

Build a command-line directory inventory that records names, types, sizes and ownership into a
timestamped report.

## Environment

Use a Linux VM or shell and a new temporary working directory containing only toy files. Do not search your home
directory or collect names or contents from personal or work files.

## Lab steps

1. Create a temporary workspace with a few sample text files, one empty file, and a nested directory.
2. Use `find` to inventory file names and types. Add size and owner information where your Linux tools provide it.
3. Filter the sample text with `grep`, count lines with `wc`, and sort a result. Compare a pipeline with output
   redirected to a file.
4. Send the final inventory through `tee` to both the terminal and a timestamped report in the workspace.
5. Try one search that should match and one that should not; explain the different exit statuses.

## Hints

```bash
find "$work" -type f -printf '%f\t%y\t%s bytes\t%u\n' | sort
grep -Rni --include='*.txt' 'sample' "$work"
find "$work" -type f | wc -l
```

Keep paths quoted. A no-match `grep` returns status 1; that is different from a command error.

## Verification

- The report has one row per expected file and its ordering is reproducible.
- A known sample word is found; a deliberately absent word is not.
- The report exists in the temporary workspace and the pipeline's exit status is understood.
- The note explains the difference between a pipe, `>`, and `>>`.

## Troubleshooting

- **No files appear:** check that `$work` is the temporary directory you created and that the files were saved there.
- **A path with spaces breaks:** quote the complete path.
- **The report is empty:** check redirection order and whether the command writes to standard output or standard error.
- **`grep` returns 1:** the pattern was not found; check the sample text before treating this as a tool failure.

## Cleanup

Remove only the temporary directory you created after checking its exact path. Keep sanitized command output in your learning record; do not use broad cleanup commands.

## Evidence to record

One short readme/note containing expected result, actual result, commands or test case
evidence, and a failure case; avoid full solution copy-pastes.

## Self-check

Navigate from memory, explain pipe and redirection order, and locate a file by name and content
without a GUI.

What would you inspect first if this stopped working tomorrow? What can you verify without asking anyone
else?
