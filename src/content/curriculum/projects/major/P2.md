# Self-Hosted Monitoring & Recovery

## Purpose

Turn a running service into an observable system you can diagnose and recover, ideally something useful
for a personal home lab.

## System scope

One or two owned services; Prometheus; Grafana; structured logs; a simple health probe; optional
local database and backup of disposable data.

## Functional requirements

Show service reachability, request/error behavior and host load. Configure a meaningful
alert with a documented response. Test one failure and one data restoration in an isolated environment.

## Non-functional requirements

No personally sensitive log ingestion; reasonable metrics retention; reproducible
deployment; monitoring must fail visibly rather than silently.

## Architecture

Own services -> metrics endpoints/exporters -> Prometheus -> Grafana dashboard/alert rule. Service
logs -> operator troubleshooting note. Test backups -> disposable restoration target.

## Trade-offs

Local Prometheus is sufficient for learning but lacks managed-service availability. A small number of
actionable signals is better than hundreds of panels. Monitoring itself needs failure detection.

## Milestones

P2.1 define health/SLI; P2.2 instrument service; P2.3 collect metrics; P2.4 dashboard and alert; P2.5
controlled outage; P2.6 test backup restoration; P2.7 incident report and improvements.

## Security and cost

Bind admin dashboards locally or behind authentication; use test data; never expose internal
monitoring ports broadly; keep the lab local wherever possible.

## Verification

Alert fires and clears with the simulated outage; metrics and logs identify failure boundaries; restore
recovers known fixtures; a new user can reproduce the dashboard.

## Deliverables

Dashboard export, alert rule, runbook, anonymized graphs, incident timeline, restore test record,
implementation notes and architecture diagram.
