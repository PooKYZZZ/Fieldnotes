# Automated Deployment Platform

## Purpose

Reduce the manual work and uncertainty involved in releasing a small backend service. A new engineer
should be able to go from a Git commit to a deployed, tested release using a documented process.

## System scope

One Python FastAPI API, Docker image, NGINX reverse proxy, GitHub Actions CI, configuration
automation (Ansible) and optional single Azure Linux VM. Terraform may provision cloud infrastructure if credits
and cost safety allow.

## Functional requirements

The app exposes a version endpoint and an operation that can be smoke-tested. Pull
requests trigger tests and build verification; a deployable artifact has an immutable version identifier. Deployment
records the version and checks application health. A documented rollback restores the previous working release.

## Non-functional requirements

Reproducible setup from a clean lab; clear access boundaries; no committed secrets;
meaningful error logs; bounded release and rollback procedure.

Suggested component architecture
Source & PR -> GitHub Actions tests/build -> versioned container image -> release approval -> Ansible/SSH
deployment -> NGINX + API -> smoke test. Terraform optionally creates network/compute, and monitoring
observes the resulting service.

## Trade-offs to explain

A VM plus Compose is cheaper and easier to operate than managed Kubernetes for one
service. A manual deployment approval is often appropriate for a learning environment. A release image is different
from source files copied over SSH.

## Milestones

P1.1 requirements and diagram; P1.2 API and tests; P1.3 Docker build; P1.4 CI; P1.5 reproducible VM
setup; P1.6 versioned deployment; P1.7 deliberate bad release and rollback; P1.8 documentation and evidence.

## Security and cost

Use least-privilege access; protect deployment secrets or use OIDC where supported; restrict
inbound SSH and HTTP; use a single small VM or local lab; record and delete billable resources.

## Verification

A clean clone builds and tests. A broken test blocks release. A version endpoint matches the deployed
artifact. A controlled failure produces a recognizable error. Rollback restores the previous verified version.

## Deliverables

Public-safe repo, diagram, architectural decision note, CI workflow, configuration files, sanitized
release logs, two deployment test records and rollback runbook.

## Primary documentation

GitHub Actions - Quickstart, Docker - Get Started, Ansible - Getting Started, GitHub - Secure deployment
and OIDC.
