# Secure Software Delivery Capstone

## Purpose

Demonstrate end-to-end delivery judgment by combining reproducible infrastructure, verified artifacts,
least-privilege security, monitoring and tested recovery. This is the final capstone, not an excuse to add every
DevOps product.

## Problem statement

A service can be developed correctly yet deployed insecurely, released without traceability or
left unrecoverable during an incident. Build a small system that closes those gaps with practical, visible controls.

## Suggested system

An owned FastAPI service deployed with Docker/Compose on an isolated local or Azure Linux
host. GitHub Actions tests and builds a versioned image. Ansible configures it; Terraform is optional for Azure.
Prometheus/Grafana measures health. Security checks and written runbooks govern release and recovery.

## Required functions

Reproducible deployment; version traceability; test/build/security gates; restricted deployment
credentials; nonsecret config template; observable health; protected rollback; one verified restoration drill.

## Service constraints

Keep data synthetic, limits and costs documented, network exposure minimized, and
deployment manual approval available. Use Kubernetes only as an optional alternative if it solves a stated problem.

## Milestones

C1 design, threat model and cost estimate; C2 provision and configure; C3 app tests and build artifact;
C4 protected release; C5 monitoring and alerting; C6 incident and rollback; C7 backup/restore; C8 final audit and
portfolio walkthrough.

## Architecture review questions

Where do secrets exist? Who can publish an artifact? How is the version identified?
Which traffic is public? What happens if the VM disappears? What telemetry reveals failed requests? What exactly
can be reconstructed from Git?

## Verification matrix

Normal release succeeds; failing test prevents release; dummy leaked credential is detected or
excluded; monitored outage creates a signal; version rollback restores functionality; test-data restore matches
known fixture; infrastructure cleanup leaves no untracked paid resources.

## Evidence

Source repository, sanitized configuration, versioned artifacts, diagram, README, architecture decision
records, threat model, CI run screenshots/logs, incident timeline, recovery proof and short demonstration script.
